# 产品设计

## 定位

AIPM 是面向 AI 产品经理的 macOS 个人 Agent 工作台，兼顾 AI Coding 和产品任务执行。用户通过对话处理项目，进入专页查看和修改产物，再根据真实结果作出下一步决策。

项目由张俊豪基于自己的学习与实践需求发起，负责需求选择、交互设计、功能整合与迭代验收，采用 AI 辅助开发。目标用户定位目前属于产品设计假设，尚无外部样本研究支持市场规模或付费结论。

## 需求如何形成

| 真实使用中的问题 | 产品决策 | 已有实现 |
| --- | --- | --- |
| 新接一个工具就多一套页面和配置 | 主要模型配置共用，按任务组织入口 | Flash / Pro 选择器、项目目录与专用页 |
| 有方案但不知道怎样做出原型 | 将手册组织为有产物和确认条件的开发流程 | 六阶段开发、阶段文件、人工评分与确认 |
| 视频被分成两个区域，修改与结果断开 | 同项目承载对话、分镜和成片 | 统一视频工作区、内嵌播放与历史导出 |
| 任务反复重试，用户不知道为什么暂停 | 区分模型写稿和本地制片，说明具体限制 | finish_video 交接、费用预留与暂停原因 |
| 模型说完成，结果却不合用 | 分开记录运行结果与用户认可 | 文件及媒体检查、人工阶段确认；统一验收口径仍在完善 |

这些材料来自一个真实使用者的持续反馈，不能代替外部用户研究。

## 一个产品开发场景

用户提出一个会议待办助手的想法，或导入现有 PRD。开发页先检查目标用户、任务和缺失信息，再明确技术选择。后端 MVP 需要给出代码与测试证据，正式前端需要提供可检查的页面。部署准备阶段整理配置与未完成事项。用户核对每个阶段的结果，决定继续、修改或暂停。

主聊天也可以直接处理选定目录。它与专用开发流程的阶段状态分别管理，不能仅凭模型回复“阶段完成”就更新人工验收。

## 一个公司调研场景

用户选择公司、客户拜访或投资机构调研，补充名称与目标。项目将公开来源、用户材料、缺口和报告版本放在一起，后续补充仍回到同一个 Pi 会话。报告结构检查与事实核验分别处理。公开源码保留该宿主流程，原私人研究资料包需由使用者自备授权副本。

## 交互取舍

聊天是主要任务入口，项目列表负责找回已有工作，高频业务进入左侧栏。技术记录折叠在执行详情中，产物尽量在工作台内展示。权限与重要操作保留明确确认，用户可以停止任务。

新版还保留玻璃材质、浅深主题和透明度选择。视觉设置用于改善长时间桌面使用，任务归属、状态与产物可读性优先处理。

## 验证与下一步

已有 PRD、交互、模型评测与验收规范初稿，整理 17 条需求和 18 条初始用例。下一步需要按同一输入开展模型对照，记录完成情况、修改次数、耗时与供应商费用，并补充外部用户任务验证。当前不填写没有数据支持的效率提升或满意度数字。
