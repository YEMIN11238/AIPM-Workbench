# 面试展示与项目讲解

## 打开介绍页后怎么讲

先用主界面说明用户怎样下达任务，再选择“方案到代码”或“实际操作电脑”回放。随后在完整功能区挑一个与岗位相关的工作区，最后讲清 Harness 的职责和自己作出的产品取舍。

不用逐项念完全部功能。AI 产品经理岗位可以重点展示开发流程、评测与验收，偏业务岗位可以展示调研和内容产物，偏 Agent 的岗位可以展开工具、会话与执行控制。

## 一段可直接使用的项目介绍

ORVYN 是我基于自己学习和实践需求做的AI 产品研发助手，主要面向需要借助 AI 完成调研与开发的产品经理。起初接入的工具需要分别配置，聊天、执行和结果分散，模型说完成之后，还要自己去找文件、运行代码并判断结果是否可用。

我把主要体验确定为用对话推进任务，再通过项目和专用工作区查看产物。执行框架选择 Pi Agent，自己主导工作台的需求、信息架构与交互，通过 AI 辅助开发实现宿主控制和业务适配。Harness 负责模型配置、工具、权限、任务状态与产物，用户可以看到过程，也能停止或确认重要操作。

产品开发是一个重点场景。用户可以从想法或 PRD 开始，按六阶段推进，留下代码、测试和阶段文件，再由用户核对并确认。Blueprint 也已经验证过生成代码、两次运行和保留上一版的迭代流程。桌面操作方面，已有 TextEdit 的窗口读取、点击、输入和截图记录。

迭代里，我重点处理了视频制作与结果分离的问题，将对话、分镜、成片预览和版本放到同一项目中。质量判断也分开记录执行结果、产物质量和用户认可，避免只凭文件存在就认定任务做完。目前已经形成可运行的 macOS 版本，独立仓库有 54 项自动化检查通过。下一步会补充统一模型对照和外部用户的真实任务验证。

## 常见追问

### 哪些是你的原创工作

产品定位、需求和优先级、工作台信息架构、对话与专页的关系、执行控制、主要模型配置及业务适配由我主导。实现采用 AI 辅助开发。Pi 与专用开源工具各自署名，我能说明它们承担什么，以及我怎样将这些能力组织为应用。

### 为什么选择 Pi

它已经提供 Agent 会话与文件、编辑、命令等执行工具，适合作为这个个人工作台的执行框架。我将产品工作的重点放在任务流程、宿主控制与产物体验上，并通过真实任务验证接通情况。

### 怎样体现 AI 产品经理的工作

把一段需求转为可执行的流程，明确输入和输出，决定哪里需要 Agent 调用工具、哪里需要用户确认。实际遇到状态中断、产物难读和视频质量不合预期后，进一步调整页面、任务交接与验收标准。

### 怎么证明它有效

区分三件事。工具是否真实执行，产物是否满足可测条件，用户是否认可结果。54 项自动化检查覆盖配置和流程，桌面操作与 Blueprint 有实际技术记录；用户任务质量需要按具体结果判断。

### 怎样管理费用

主要模块共用已保存的模型连接，Flash 与 Pro 可在输入区选择，进行中的任务保留启动模型。特定视频轮次有费用上界与预留机制，本地渲染与模型创作分别记录。费用上界不冒充供应商实账。

### 遇到过什么失败

视频曾经在技术上可播放，但用户不接受画面效果。我据此将媒体合格与审美认可分开，强调分镜、关键帧和实际播放检查。另一个问题是制作入口割裂，后来改为同一项目承载对话、制作与预览。

### 下一步优先做什么

按真实任务补齐统一评测，再完善主聊天与专用开发流程的关联和失败恢复。对外验证时记录任务完成情况、用户修改次数、耗时与费用，先取得数据，再判断实际收益。
